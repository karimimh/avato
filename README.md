# Avato (آواتو)

This repository contains only the production-sensible software foundation for Avato. It wires together a minimal Next.js frontend, a monolithic FastAPI/Celery Python application, and local infrastructure. No product workflows or domain models are implemented.

## Repository structure

```text
.
├── backend/             FastAPI, SQLAlchemy, Alembic, and Celery codebase
│   ├── app/
│   │   ├── api/         API router and infrastructure health check
│   │   ├── core/        Central environment-backed settings
│   │   ├── db/          SQLAlchemy base, engine, and session setup
│   │   └── workers/     Celery application (no tasks)
│   ├── migrations/      Alembic environment and future revisions
│   └── tests/           Minimal test foundation
├── web/                 Next.js App Router frontend
├── nginx/               Local reverse-proxy configuration
├── docs/                Project documentation supplied separately
├── docker-compose.yml   Complete local development stack
└── .env.example         Documented local configuration
```

## Prerequisites

- Docker with Docker Compose
- Node.js 22 and npm 11 for host-based frontend development
- Python 3.12 or 3.13 and [uv](https://docs.astral.sh/uv/) for host-based backend development
- FFmpeg is only required on the host when running future media code outside Docker; it is already installed in backend and worker images

## Environment setup

```bash
cp .env.example .env
```

The checked-in values are local-development defaults, not production credentials. Change every password and access key outside local development. `OPENAI_API_KEY` is a reserved, unused placeholder and can remain blank.

## Install dependencies

Frontend dependencies are locked in `web/package-lock.json`:

```bash
cd web
npm ci
```

Backend dependencies are locked in `backend/uv.lock`:

```bash
cd backend
uv sync
```

## Start development with Docker

From the repository root:

```bash
docker compose up --build
```

The services are then available at:

- Nginx entry point: <http://localhost:8080>
- Frontend directly: <http://localhost:3000>
- API directly: <http://localhost:8100>
- API health check: <http://localhost:8080/api/health>
- MinIO API: <http://localhost:9100>
- MinIO console: <http://localhost:9101>

PostgreSQL and Redis are also published on their standard ports for local tooling. Override any published port with the corresponding `*_PORT_FORWARD` variable if it conflicts on your machine.

## Run processes on the host

Start PostgreSQL and Redis (and optionally MinIO) in Docker:

```bash
docker compose up -d postgres redis minio
```

When backend processes run on the host, override the container hostnames from `.env`:

```bash
cd backend
DATABASE_URL=postgresql+asyncpg://avato:avato-dev-password@localhost:5432/avato \
CELERY_BROKER_URL=redis://localhost:6379/1 \
CELERY_RESULT_BACKEND=redis://localhost:6379/2 \
uv run uvicorn app.main:app --reload --port 8100
```

Run the worker in another terminal (it has no registered product tasks):

```bash
cd backend
CELERY_BROKER_URL=redis://localhost:6379/1 \
CELERY_RESULT_BACKEND=redis://localhost:6379/2 \
uv run celery -A app.workers.celery_app worker --loglevel=INFO
```

Run the frontend:

```bash
cd web
npm run dev
```

## Database migrations

SQLAlchemy currently has an empty declarative base: there are no product models or tables. When models are added in a later implementation phase, import their metadata into `app.db.base`, then generate and review a migration:

```bash
cd backend
uv run alembic revision --autogenerate -m "describe the schema change"
uv run alembic upgrade head
```

Never treat autogenerated migrations as unreviewed output. Commit reviewed migration files with the code that depends on them.

## Inspect and stop local services

```bash
docker compose ps
docker compose logs -f backend worker web
docker compose down
```

To reset all local PostgreSQL, Redis, MinIO, dependency, and build-cache volumes:

```bash
docker compose down --volumes --remove-orphans
```

The volume-reset command permanently removes local development data. It does not remove source files.

## Foundation decisions

- FastAPI and Celery share one Python package rather than being separate services or codebases.
- SQLAlchemy uses its async engine with `asyncpg`; Alembic is configured for async migrations.
- Redis databases are separated by purpose: general configuration (`0`), Celery broker (`1`), and Celery results (`2`).
- MinIO provides an optional self-contained S3-compatible endpoint, but no bucket is created and no storage operations exist.
- `faster-whisper` is installed and FFmpeg is present in backend images, but no model download or media-processing code exists.
- shadcn/ui configuration and utility dependencies are ready, while no component has been generated prematurely.
- TanStack Query is provided at the application root with no product queries.
